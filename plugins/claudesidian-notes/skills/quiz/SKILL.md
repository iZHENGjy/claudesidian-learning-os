# Skill: quiz

## Role

让用户**发现自己哪里没懂**。题目从复习库和讲义里出，按概念记录对错，下次优先考没掌握的地方。

## Files

```
01_Projects/<CODE>_课名/复习库/
├── 00-总览.md          掌握度看板（只放汇总数字）
└── 掌握度/<主题>.md     每个概念的作答次数、答对次数、最近日期、状态、错因
```

## Workflow

### Step 1: 找到复习库

Glob `01_Projects/<CODE>_*/复习库/00-总览.md`。不存在 → 告诉用户"这门课还没有复习库，先说'做 <CODE> 的复习库'"，停止。

### Step 2: 选这一轮考什么（必须问）

读 `00-总览.md` 的掌握度看板，用 AskUserQuestion 给出按现状生成的选项：

- 有 ⬜ 未测主题 → "摸底：<未测主题>"
- 有 🟥 / 🟨 主题 → "补弱：<最弱的主题>"
- 总是给 → "自选主题"
- 全部 🟩 / 🟦 → "难题复习"

### Step 3: 出题

1. Read 目标主题的 `题库/<主题>.md` 和它"考点"链接指向的讲义小节
2. 补弱时再读 `掌握度/<主题>.md`，挑 🔴 未解决的概念，**换个情境重新问**（不照抄上次的题）
3. 按 `references/quiz-rules.md` 出 **4 道选择题**（必读，零提示原则）
4. 每轮最后可加 **1 道复述题**：让用户不看笔记，用自己的话讲一个 🔴 概念的因果链（用讲义"用自己的话说"里的关键环节判分）

### Step 4: 提问

AskUserQuestion：4 题，每题 4 个选项，单选；标题 "Q1. 主题"（≤ 12 字）；选项描述中性，不暗示对错。复述题用普通对话问，等用户回答。

### Step 5: 判分讲解

1. 结果表：题目 / 正确答案 / 你的答案 / 对错
2. 答错的题：一两句讲清错在哪，链接讲义小节和易错点
3. 复述题：逐个关键环节说"有 / 缺 / 错"，缺哪个环节就补哪个，不重讲整节

### Step 6: 更新文件

**`掌握度/<主题>.md`**（不存在则按模板创建）：

- 新概念 → 加一行；答错的同时在"错因"段加一条
- 🔴 概念这次答对 → 次数、答对 +1，状态改 🟢，**保留**错因（学习历史）
- 🟢 概念这次又错 → 次数 +1，状态改回 🔴，更新错因

```markdown
# <主题> · 掌握度

| 概念 | 作答 | 答对 | 最近 | 状态 |
|---|---|---|---|---|
| 质量平均 vs 摩尔平均速度 | 2 | 1 | 2026-11-03 | 🔴 |

### 错因

**质量平均 vs 摩尔平均速度**
- 混淆：算质量扩散速度时减了摩尔平均速度 V
- 要点：质量基减 v，摩尔基减 V → [[L02_…#2.3 扩散速度（Diffusion velocity）（p.12–13）]]
```

**`00-总览.md`**：从各 `掌握度/*.md` 重新汇总每个主题的答对 / 答错 / 正确率，更新等级（🟥 0–39% · 🟨 40–69% · 🟩 70–89% · 🟦 90–100% · ⬜ 未测），刷新"薄弱点"段（🔴 概念 → 讲义出处 → 易错点）。看板只放汇总，不写每轮记录。

### Step 7: 报告

一句话总结这一轮（几对几错、新增几个 🔴、哪个主题升降级），给出下一轮建议。

## Rules

1. **零提示** — 选项和描述不泄露答案，正确选项位置随机
2. **只考笔记里有的内容**
3. **每轮都更新掌握度和看板**
4. **不改题库和讲义** — 发现题目本身有错，报告用户，由用户决定是否修

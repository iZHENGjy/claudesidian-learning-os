## §3b — Sub-agent "块 1/2/3 输出" 协议

每个 Agent 读 `_attachments/_pages/<page>.png` + MinerU md 对应段，**输出三块**。

### 块 1 — 逐页核对（每页一段）

```
### Slide X: [页面标题]
**MinerU 已抽**: (从 full.md 对应段落复制)
**vision 补漏**: (MinerU 漏的文字 / 公式 / callout)
**误识修正**: (公式 / 字符纠正)
**本页图表**: (描述 + 引用 hash)
```

### 块 2 — 图片重命名清单

本段所有 MinerU 抽出的图，**全部都要列**：

| 旧 hash | 新文件名 | 类型 |
|---|---|---|
| `45f8a3b9c1d2e4f5...完整 32 位` | `<CODE>_L##_p<2位页码>_<topic-slug>_<type>.jpg` | concept |

⚠️ **旧 hash 必须给完整 32 位**（从 full.md 里 `![](images/<hash>.jpg)` 直接抄），不要缩写 — 主线程要用它做精确替换。

⚠️ **页号映射**：PNG `<prefix>_pageNN.png` 中的 NN 直接 = slide N，新名前缀写 `p<NN>`。不要做任何 ±1 偏移猜测（过往 sub-agent 误以为"封面占一页 → slide=page+1"导致整批图错位 +1）。

`type` 取值：`concept` / `data` / `flow` / `formula` / `table` / `decor`

### 块 3 — 嵌入推荐清单

只列推荐度 ≥ 3：

| 新文件名 | 推荐度 | 理由 | 建议放哪个知识块 |
|---|---|---|---|
| ... | 5 | ... | ... |

推荐度尺度：5 必嵌 / 4 强烈建议 / 3 可嵌可不嵌 / 2-1 不必列。

### 纯 vision 模式（2a 失败时）

无块 2/3（没 MinerU 图），只输出块 1。

## §3c — 主线程聚合（mv + 同步 full.md + verify Read 三步）

收齐所有 sub-agent 报告后，**主线程做**：

### 1. 批量 mv

按"块 2 重命名清单"把 `_attachments/<pdf_stem>/images/` 下的 hash 文件名改成语义名。

### 2. 同步 full.md 图引用（❗易漏）

批量替换 `_attachments/<pdf_stem>/full.md` 里所有 `![](images/<旧 hash>.jpg)` 为 `![](images/<新语义名>.jpg)`。

**不做这一步的后果**：笔记本身没事（它用新名），但 `full.md` 在 Obsidian 里所有图全坏（指向已不存在的 hash 文件），留档的 full.md 也是坏的。

- PowerShell 实操：读 full.md 内容 → 对块 2 清单每行做 `-replace [regex]::Escape($oldHash), $newName` → 写回。
- 块 2 清单里的 hash 必须是**完整 32 位**（不是缩写），否则替换不到。

### 3. verify Read

对"块 3"中**推荐度 ≥ 4** 的图，Read 一次亲眼看 — 确认 sub-agent 描述准、值得嵌。每张图打三种 verdict：

- **VERIFIED 嵌入** — 进笔记
- **VERIFIED 跳过** — 不进笔记（sub-agent 推荐度高估）
- **追加嵌入** — sub-agent 没推荐但 Read 时发现值得嵌

## §4 — 笔记生成规则（讲解型笔记）

按 `${CLAUDE_PLUGIN_ROOT}/skills/ingest-lecture/assets/lecture-topic.md` 模板写。笔记的用途是**第一次学这一讲时读懂它**，期末复习另有 `build-review-vault` 生成的复习库，所以这里不追求压缩，追求讲清楚、讲对。

### 4.1 读者

目标读者 = 学过前置课程但有些生疏的本科生。笔记要能脱离 PPT 独立读懂：正文里提到的课件图必须嵌入，读者永远不需要回去翻 PDF。

### 4.2 开头三件套

1. **一眼看懂**：≤ 3 句、≤ 1 个术语，"一个熟悉的例子进去 → 得到什么 → 为什么有人要它"。写不出来说明还没理解这一讲，先回去读课件。
2. **阅读路线表**：每个部分一行，写课件页码和"读完能回答的一个真实问题"。
3. **前置知识表**：本讲用到但没讲的知识，标"默认已掌握"或"在 §x.y 补充"。

### 4.3 每个知识点的固定结构（`###` 小节）

每个 `###` 小节都按同一顺序，长度相近；一节最多引入 1–2 个新术语，超了就拆成两节：

1. **为什么需要它** — 不懂它会卡在哪，具体失败场景。**不许以术语、定义或公式开头。**
2. **它怎么工作** — 连贯讲解文字，从输入走到输出，用课件自己的例子。要点列表只能在讲完之后用来归纳，不能用来引入新概念。
3. **课件里的概念** — 课件的命名、定义、每一个要点，公式用 `\tag{部分.序号}` 编号。
4. **实例**（若课件有例题）— 见 §4.5。
5. **专业说法** — 一两句从业者的说法，中文 + `*EN: …*`。
6. **优缺点** — 最后一句是它留下的问题，接到下一节的"为什么需要它"。
7. **用自己的话说** — 折叠块：3 个可勾选的关键环节 + 一段 ≤ 5 句的参考说法。它代替小结段落，不要再另写总结。

课件里只是补一句的小点，可以缩成 1、3、6 三段，但仍然从问题开始。

### 4.4 每个部分（`##`）结尾

- **误区与陷阱**：2–3 条 `> [!failure]`。标题写成学生会理直气壮持有的错误说法；正文依次是**反例（带数字）→ 为什么不对（一条因果链，链接讲原因的小节）→ 正确说法（中英）**。来源优先级：课件自己的警告 > 本讲实例里真实会算错的地方 > 已核对的教材。凑不满就少写，不许编一个没人会犯的误区。
- **暂停**：一个"为什么"问题 + 3 个可勾选的关键环节 + 1 道新情况的预测题（答案唯一，答案再折叠一层）。

### 4.5 课件例题：必须算完、必须验算

- 课件上的每一道例题都写成 `> [!example] 实例 x.y` 块，**算到数字结果为止**，最后一行 `**计算结果：**` 写**题目问的那个量和单位**（问质量通量就给 kg/(m²·s)，不能只给摩尔通量）。
- 每一步先写公式，再逐行代数（`\begin{aligned}`），读者能看到每个数从哪来。
- 单位先全部换成 SI 再代。分子量用 kg/mol 时写明，避免 g/kg 混用。
- **验算脚本（强制）**：把本讲所有实例、练习答案里的数字写进 `_attachments/<pdf_stem>/verify.py`，每个结果一条 `assert`（能用 `fractions.Fraction` 精确算的就精确算），跑通才算完成，frontmatter `verified:` 写结果。脚本不过 → 改笔记，不许改断言凑数。
- 例题如果有一步依赖课件没讲的条件（如"稳态下浓度线性分布"），在那一步当场说明。

### 4.6 课件以外的内容：要么有出处，要么别写

- 课件内容照课件说；转述或补步骤后回头核对原页，确认没改意思。
- 课件以外的内容（补充、"某人提出"、"因为 X 所以 Y"的自己的解释）写之前**先上网核对**教材、论文或官方资料（不用博客、论坛、AI 生成页面当证据），写成 `> [!info]- 补充：…` 折叠块并以 `来源：[作者, 年份]` 结尾，完整条目进 `### 参考文献`。
- 核对不了的：删掉，或标 `（待核实：…）`。**绝不凭记忆当事实写。**

### 4.7 链接与图片

- `[[链接]]` 只链接 vault 里**已存在**的笔记或本笔记内的标题（`[[#1.2 …|§1.2]]`）。不为"可能以后会建"的概念页预留链接；跨讲引用写到对方的标题。
- 图片 `![[file.png]]` 紧跟讲到它的地方，后面一行写"看图里的什么"。
- 一组并列的东西（3 种速度、4 种公式写法）逐个讲完后，用一张对比表收尾。

### 4.8 结尾

- **本讲小结**：每个概念一行（一句话 + 关键公式）。
- **练习**：≥ 8 题检验理解（≥ 60% 问"解决什么 / 为什么"，≥ 2 题连接两个概念），答案折叠。计算题留给复习库和 tutorial。
- **术语中英对照**、**参考文献**（若有补充）。
- **个人补充**：留空给用户，AI 不填。
- **PPT 原文**：折叠在最末，逐页要点，保证覆盖可追溯。

### 4.9 不再做的事

- 不写"我的疑问"（AI 以用户口吻写的问题，没人回答）。需要引导思考的，放进"暂停"的预测题。
- 不在正文里混入未标注的 AI 延伸。
